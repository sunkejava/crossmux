# Smart Standby protocol

Smart Standby separates data collection and layout from the constrained ESP32-C3 firmware. The .NET 10 service owns templates, external data sources, font rendering, grayscale conversion and schedules. The firmware owns connectivity, validated download, SD caching and display.

## Device identity and topic

The feature reuses the stable AirPage device ID stored at `/.crosspoint/airpage_device_id`.

Set `File Sync Server URL`, `Smart Standby MQTT Host`, and `Smart Standby MQTT Port` from the reader's Web Settings page. The broker host and port must match the service's `SmartStandby` configuration. The first implementation supports anonymous MQTT connections; put a private broker behind a trusted LAN/VPN rather than exposing an unauthenticated listener to the public internet.

```text
crossmux/device/{deviceId}/standby/v1
```

Notifications are retained, QoS 1 JSON messages. The current firmware treats the payload as a bounded wake-up signal rather than parsing it; this keeps MQTT RAM use independent of template complexity.

## Image endpoint

```http
GET /api/v1/standby/{deviceId}/image.bmp
```

The response is an 800×480 BMP generated by the service. The reader streams it to:

```text
/.crosspoint/smart-standby/current.bmp.part
```

After validating the BMP header, it moves the existing image to `.bak`, promotes `.part`, and removes the backup. A failed download or invalid image never replaces the last valid page.

## Admin endpoints

All endpoints below require `X-Api-Key` when `Sync:ApiKey` is configured.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/admin/standby/templates` | List templates |
| `POST` | `/api/admin/standby/templates` | Create or replace a template |
| `POST` | `/api/admin/standby/templates/{id}/publish` | Resolve, render and publish now |

The background publisher refreshes every `SmartStandby:RefreshSeconds` and republishes every enabled template.

## Template model

- Canvas: bounded from 320–1200 pixels; device presets use 800×480.
- Widgets: up to 64 `text`, `progress`, `divider`, or remotely sourced `image` widgets. Each image is capped at 4 MiB before decoding.
- Data sources: up to 8 HTTP JSON endpoints, 32 bindings per source and 12 optional headers.
- Values: static fallback values and server-generated `date`, `time`, and `now` variables.
- Binding: `{{variable}}` placeholders in widget titles and values.

Data-source failures retain the template's static fallback values for that render. HTTP requests time out after 12 seconds so one provider cannot indefinitely block the refresh cycle.

## Power and memory behavior

MQTT is active only while the remote Standby face is selected. The face allocates PubSubClient's normal bounded packet buffer; image bytes never enter that buffer. HTTP response bytes stream directly to SD. Leaving Standby disconnects MQTT and releases Wi-Fi owned by the face.

Continuous live updates require the reader to remain in Standby, which intentionally prevents deep sleep. E-ink consumes no power to retain an image, but continuous Wi-Fi/MQTT does consume battery; use external power for always-on dashboards.
